MILESTONE 2 — STEPS TO COMPLETE
================================

This document outlines the steps required to extend the Milestone 1 project
into Milestone 2. Work continues inside the existing Group24/ folder. Do NOT
create a new folder. Add new files and modify existing ones in place.

Final folder layout:
  local_html/Group24/
    index.php
    about.php
    color.php             (UPDATED)
    print.php             (UPDATED)
    colors.php            (NEW — Color Selection page)
    colors_dynamic.php    (NEW — outputs CSS from DB)
    db.php                (NEW — DB connection, included via require)
    style.css             (UPDATED)
    print.css
    images/
    (any other files needed)


----------------------------------------------------------------
STEP 0 — Database setup (do this first; everything depends on it)
----------------------------------------------------------------
0.1  Create a MySQL/MariaDB database for the project (use the class server
     credentials).
0.2  Create a table named `colors` with these columns:
       - id        INT, PRIMARY KEY, AUTO_INCREMENT, NOT NULL
       - name      VARCHAR, UNIQUE, NOT NULL
       - hex_value VARCHAR(7), UNIQUE, NOT NULL   (e.g. "#FF0000")
0.3  Pre-populate with the 10 Milestone 1 colors and correct hex values:
       Red #FF0000, Orange #FFA500, Yellow #FFFF00, Green #008000,
       Blue #0000FF, Purple #800080, Grey #808080, Brown #A52A2A,
       Black #000000, Teal #008080
     (Confirm exact hex values match what you used in Milestone 1.)
0.4  Create db.php:
       - Defines DB host, name, user, password.
       - Opens a PDO (recommended) or mysqli connection.
       - Use prepared statements everywhere to prevent SQL injection.
       - Set PDO error mode to EXCEPTION.
       - Every page that touches the DB starts with: require 'db.php';


----------------------------------------------------------------
STEP 1 — Build the Color Selection page (colors.php)
----------------------------------------------------------------
1.1  Add "Color Selection" to the navigation on every page (index, about,
     color, print, colors). Keep nav markup consistent across pages.
1.2  At the top of colors.php: require 'db.php';
1.3  Display the current colors table (name + hex swatch + hex code).
1.4  ADD a color:
       - Form with inputs: name (text), hex_value (text or <input type="color">).
       - Validate server-side: non-empty, hex format /^#[0-9A-Fa-f]{6}$/.
       - Before insert, check uniqueness of name AND hex_value (SELECT ... WHERE
         name = ? OR hex_value = ?). If duplicate, render a non-intrusive
         on-page error (e.g. a styled <div class="error">). NO alert().
1.5  EDIT a color:
       - Let the user pick an existing color (e.g. dropdown of names).
       - Show editable name and hex_value fields pre-filled with current values.
       - On submit, validate uniqueness against OTHER rows (WHERE id <> ?).
       - On conflict, show on-page error and do not update.
1.6  DELETE a color (two-step / confirmation required):
       - Step A: user selects a color and clicks "Delete".
       - Step B: page re-renders showing "Are you sure you want to delete X?"
         with explicit Confirm and Cancel buttons. Only delete after Confirm.
       - Do NOT use a dropdown that deletes on selection change.
       - Before deleting, count rows: if COUNT(*) < 2, refuse and show a
         non-intrusive error explaining at least 2 colors must remain.
1.7  Use POST for all add/edit/delete forms. Use prepared statements.
     After a successful write, redirect (PRG pattern) to avoid resubmission.


----------------------------------------------------------------
STEP 2 — Dynamic stylesheet (colors_dynamic.php)
----------------------------------------------------------------
2.1  At the top:
       <?php
       require 'db.php';
       header('Content-Type: text/css');
       ?>
2.2  Query SELECT id, name, hex_value FROM colors;
2.3  For each row, emit a CSS rule keyed by something stable (recommend the
     id, since name/hex can change). Example output:
       .color-3 { background-color: #FFFF00; }
     Or key by a sanitized name. Be consistent with what color.php uses.
2.4  Link it from color.php like a normal stylesheet:
       <link rel="stylesheet" href="colors_dynamic.php">


----------------------------------------------------------------
STEP 3 — Update color.php (Color Coordinate page)
----------------------------------------------------------------
3.1  require 'db.php' and load all colors from the `colors` table.
3.2  Replace the hard-coded dropdown options with options generated from the
     DB. Each <option value="..."> should carry an identifier that matches
     the keys used in colors_dynamic.php (id is recommended). Also expose
     name + hex to JS (e.g. via a JSON blob in a <script> tag or data-* attrs).
3.3  Top table: in EACH row, beside the dropdown, add a radio button. All
     radios share the same name attribute (e.g. name="active_color") so only
     one can be selected at a time. The radio in the first row is checked
     by default on page load.
3.4  Painting (JavaScript):
       - Click handler on every non-header cell of the lower grid.
       - On click, read which radio is currently selected -> that row's
         dropdown value -> apply that color's CSS class to the cell (so the
         color comes from colors_dynamic.php, not inline styles).
3.5  Coordinate tracking (JavaScript):
       - Each grid cell knows its coordinate (e.g. A1, B3). Set this with a
         data-coord attribute when generating the grid.
       - Maintain a JS map: { colorId: [coords...] }.
       - When a cell is painted: remove the coord from any previous color's
         list, add it to the active color's list.
       - Render each row's right-column cell as a comma-separated list,
         sorted lexicographically: by letter first, then by numeric value
         (so A1, A3, B2, C1 — NOT A1, A3, B2, C1 as plain string sort which
         would mis-order A10 vs A2; sort numerically on the number portion).
3.6  Recolor on dropdown change:
       - When a dropdown is changed to a new valid color, swap the CSS class
         on every cell that was painted with the old color so it now shows
         the new color. Update the internal map's key as well.
3.7  Duplicate-prevention validation:
       - Before accepting a dropdown change, check whether any OTHER dropdown
         already has that color selected.
       - If duplicate: revert the dropdown to its previous value and show a
         non-intrusive on-page message (e.g. a <div id="msg"> that you
         populate, optionally fade out after a few seconds).
       - Do NOT use alert(). Track each dropdown's "previous value" in JS so
         you can revert cleanly.


----------------------------------------------------------------
STEP 4 — Update print.php (Print View)
----------------------------------------------------------------
4.1  Decide on transport: pass coordinate data from color.php to print.php
     via either GET (query string) or POST (hidden form). Pick ONE and stick
     with it. POST is cleaner for larger payloads; GET is easier to test.
     Suggested payload: a JSON-encoded map of colorId -> [coords].
4.2  On color.php, add a "Print View" button/link that submits the current
     state to print.php using the chosen method.
4.3  In print.php:
       - require 'db.php' and re-load color rows so you can show
         "Name — #HEX" in the left column of the top table.
       - Show the right-column coordinate lists exactly as on color.php
         (same sort order).
       - Do NOT render radio buttons.
       - Render the lower coordinate grid completely BLANK (no fill colors;
         only the headers and grid lines). The activity is to color by hand.
4.4  Header: keep the company logo + name from Milestone 1.
4.5  Layout: must fit on one 8.5 x 11 inch page, portrait. Use print.css
     (and/or @media print rules) to control sizing.
4.6  Greyscale on print:
       - In print.css (or @media print), force greyscale, e.g.:
           @media print {
             html { filter: grayscale(100%); -webkit-print-color-adjust: exact; }
           }
       - Verify in the browser's Print Preview that no color appears.


----------------------------------------------------------------
STEP 5 — Update style.css and navigation
----------------------------------------------------------------
5.1  Add a "Color Selection" link to the shared navigation on every page.
5.2  Style the new on-page error/notice element (e.g. .error, .notice) so
     messages are visible but non-intrusive.
5.3  Style the colors.php tables and forms so they match the rest of the site.


----------------------------------------------------------------
STEP 6 — Security & robustness checklist
----------------------------------------------------------------
- Use prepared statements for every SQL query (no string concatenation).
- Validate and sanitize all user input server-side (name length, hex format).
- Escape all output with htmlspecialchars() when echoing user/DB data.
- Use the POST/Redirect/GET pattern after successful add/edit/delete.
- Do not expose DB credentials; keep them only in db.php (and consider
  placing db.php outside the web root or protecting it).
- Confirm uniqueness checks are case-handled the way you want (the DB
  UNIQUE constraints will enforce it regardless; use them as the source
  of truth and catch the duplicate-key exception).
